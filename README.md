## 第一次来，从这里开始

| 你现在想做什么 | 最短路径 |
|---|---|
| 先看看完整成品 | 按下方方式 A 启动，在终端显示的网址后加 `?mode=demo`；不需要到杭州，也不读取真实定位 |
| 做一套自己的地图 | 直接把“地点 + 礼物”按方式 B 的提示词发给 AI；不需要先理解代码或填写坐标 |
| 修改或贡献代码 | 完成本地安装后执行 `npm run setup:e2e`，再用 `npm run verify` 做一次完整检查 |

公开模板首屏也提供“进入无需定位的完整演示”。演示进度与正式路线分开保存，不会污染真实活动记录。为收件人部署私人正式版时，把 `src/config/experience.ts` 中的 `publicDemo.enabled` 改为 `false`。

## 你可以用它做什么

- 为生日、纪念日、求婚或城市寻宝制作一条私人探索路线。
- 在抵达前隐藏地点与礼物，进入指定半径后再揭晓。
- 用手绘地图显示实时位置、朝向、狗爪轨迹和目标点。
- 在每一站加入参考照片与本地照片匹配任务。
- 把进度、照片和视觉模型保存在设备端，并通过 PWA 离线使用。
- 为定位、方向和照片失败保留现场应急控制台。

## 两种开始方式

### 方式 A：先运行杭州示例

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

打开终端给出的地址即可查看。相机、定位、方向和 PWA 离线能力需要 HTTPS；本地 HTTP 主要用于页面与流程开发。

第一次预览建议打开终端网址后加上：

```text
?mode=demo
```

演示页面会显示“模拟抵达当前地点”和“跳过照片，查看揭晓”，可以在桌面上走完整套流程。正式入口不会自动模拟定位。

第一次运行完整浏览器测试，需要额外安装 WebKit：

```bash
npm run setup:e2e
npm run verify
```

`npm run verify` 会依次检查隐私、文档链接、单元测试、构建、PWA 升级、iPad WebKit 完整流程和 TypeScript。

### 方式 B：让 AI 为你生成一套新地图

用户只需要告诉 AI“想去哪些地方、每个地方准备什么礼物或体验”。坐标、地图数量、路线分组、世界观、谜面和技术配置都由 AI 处理。

1. 在已经打开本仓库的 AI 编程工具中，直接发送下面的提示词；或者复制填写 [最简需求表](docs/PROJECT_BRIEF.template.md)。
2. AI 查询地址、坐标和真实步行路线，按步行可达范围规划地图与转场，并返回一张最终路线表。
3. 你只确认地点、入口、顺序和礼物有没有选错。
4. AI 再生成文案、地图和代码，并执行完整验证。

可直接发给 AI：

```text
请基于这个 Exploration Atlas 仓库，为我制作一套新的生日探索地图。
先完整阅读 README.md、AGENTS.md 和 docs/CUSTOMIZE_WITH_AI.md。

我想按顺序去这些地方：
1. [地点名称、地址或地图链接]，到这里揭晓[礼物或体验]
2. [地点名称、地址或地图链接]，到这里揭晓[礼物或体验]
3. [地点名称、地址或地图链接]，到这里揭晓[礼物或体验]

用户只负责提供地点和礼物，不要求用户填写经纬度。
请主动查询地点并转换为 WGS-84，获取相邻地点的真实步行距离和时间，不要只用直线
距离。每张地图只包含一个连续步行可达的范围，超限或存在道路阻隔时自动拆图并增加
转场。沿用仓库现有美术风格生成谜面、解锁文案与终章。先只返回一张路线确认表，
不要立即修改代码。确认后直接实现、测试和交付；只有地点存在歧义或路线确实冲突时才追问。
```

## 用户最终只需要确认

| 类别 | 谁负责 |
|---|---|
| 地点与礼物 | 用户提供想去的地方，以及每一站要揭晓的礼物/体验 |
| 地址消歧 | AI 查询候选地点和入口，用户只确认“是不是这里” |
| 坐标 | AI 从地点或地图链接获取并转换为 WGS-84，用户不手动输入 |
| 地图与交通 | AI 查询真实步行距离/时间，检查累计路程与道路阻隔；每张地图对应一个步行可达范围，用户只确认结果 |
| 世界观与文案 | 默认沿用现有风格，由 AI 自动生成；用户只修改不喜欢的句子 |
| 技术与兜底 | AI 使用项目默认值实现和测试，不逐项让用户填写 |
| 真实参考照片 | 初版可使用仓库示意图；正式活动照片需要用户在确认后的触发位置拍摄或提供 |
| 现场彩排 | 自动测试由 AI 完成；最终仍需拿活动当天的设备实走一次，确认入口、定位和离线缓存 |

具体自动生成规则和验收门槛见 [从零定制指南](docs/CUSTOMIZE_WITH_AI.md)。

AI 查询地点和步行路线时需要访问最新地图或路线服务；生成新的手绘底图还需要可用的图像生成能力。缺少其中一项时，AI 应明确标记“待核验/待替换”，不能用猜测数据冒充最终成品。

## 项目结构

```text
src/config/experience.ts   收件人称呼、通用文案、可选媒体、制图人入口
src/config/story.ts        杭州示例的地图、地址、坐标、关卡和剧情
src/components/            信封、地图、照片任务、终章和应急控制台
src/lib/                   地理投影、坐标转换、照片匹配和本地存储
public/assets/maps/        可运行的示例地图
public/references/         无真人的照片任务示意图
public/custom/             用户自己的可选片头与音乐
docs/                      定制流程、美术说明、需求表和杭州示例
tests/                     地理、剧情、PWA 与 iPad WebKit 测试
```

通常只需要重点编辑两个配置文件：

- [experience.ts](src/config/experience.ts)：称呼、章节表达、终章、可选片头、音乐和应急入口。
- [story.ts](src/config/story.ts)：地图分组、路线锚点、真实坐标、礼物、谜面、参考图和评分模式。

## 项目正常运行的前提

- 必须部署在 HTTPS 下，浏览器才会可靠提供定位、方向和 Service Worker。
- 当前模板的静态资源与 Service Worker 使用域名根路径（`/`）；默认应部署在独立域名根目录。若发布到 `example.com/repo/` 这类子路径，需要先统一改造 Vite `base`、资源路径与 Service Worker scope。
- 浏览器定位返回 WGS-84；运行时目标坐标也必须统一为 WGS-84。
- 手绘地图必须有明确地理边界，或有足够的“真实坐标 ↔ 画面坐标”锚点。
- 30 米级抵达判定适合室外或建筑入口，不保证在高楼深处稳定工作。
- iPad 纯 Wi-Fi 机型可能只有粗定位；正式使用前必须拿目标设备现场彩排。
- 首次加载需要联网，确认离线缓存完成后才能依赖断网模式。
- 照片匹配是现场游戏机制，不是身份识别，也不应被用于安全判断。
- 制图人口令会打包进静态前端，只能防误触，不能当作真正的秘密。

## 可选片头与音乐

公开模板默认不带片头视频和背景音乐，也不会请求不存在的媒体。

如需启用：

1. 把你有权使用的文件放入 `public/custom/`。
2. 在 `src/config/experience.ts` 中核对文件名。
3. 将相应 `enabled` 改为 `true`。
4. 重新执行完整构建和断网测试。

片头制作与美术衔接方法见 [美术与素材指南](docs/ART_AND_ASSETS.md)。不生成片头时，体验会直接从网页信封开始，主流程不受影响。

## 示例、隐私与公开发布

- [杭州示例路线](docs/HANGZHOU_EXAMPLE.md) 保留公开地址和地图，作为结构参考。
- 真人参考照已替换为 SVG 示意图。请用自己的现场照片替换，但必须获得出镜者同意。
- 不要提交原始照片、聊天记录、账号、私人链接、家庭附近彩排坐标或带个人元数据的媒体。
- 如从私人项目迁移，请新建一个干净仓库发布；仅删除当前文件不会清除旧 Git 历史。
- 公共 Demo 建议关闭制图人入口，或明确说明它只是演示功能。

发布前请执行：

```bash
npm run verify
```

如需检查你自己的姓名、账号、旧口令或私人地点，可在仓库根目录创建已被忽略的
`.private-audit-terms`，每行填写一个不可公开的词，再执行 `npm run audit:public`。
